# LZMA2 Flush Strictness Measurements

Measured 2026-09-12 EDT on an AMD Ryzen Threadripper 3990X, Linux x86_64,
Zig 0.16.0, canonical Nix ReleaseFast builds. Baseline revision:
`33dd4bc56799410aab4291caaf731c93ced5c823`. The final implementation is committed
with this report. [Raw samples and executable hashes](2026-09-12-lzma2-flush.json)
include every measured candidate, including rejected and interrupted runs.

## Final Comparison

Each sample performs ten verifications of the same 1 MiB Gaussian-byte payload
inside an 851422-byte LZMA2 archive. The Zig verifier reads the archive once and
verifies in memory ten times. The C CLI batch starts ten processes and reads the
archive on each invocation. CPU means user plus system time.

| Path | Before wall | After wall | Wall change | Before CPU | After CPU | CPU change |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Streaming Zig verify | 744.56 ms | 749.80 ms | +0.70% | 739.25 ms | 744.32 ms | +0.69% |
| Retained C CLI | 584.57 ms | 577.60 ms | -1.19% | 579.77 ms | 572.89 ms | -1.19% |

Median paired CPU changes were +0.79% and -1.24%, respectively. These are
measurements on one host and corpus, not a claim of zero regression or a
cross-platform speedup. Other fleet activity was uncontrolled. No project
builds ran during measurements.

Hyperfine ran twelve alternating-order before/after pairs, each with one warmup
and one measured run per command. Commands were pinned to CPU 24.
`MUTE_DEBUG_STATUS` was unset; all binaries passed a pristine preflight and their
captured output contained no `DEBUG BUILD` marker.

## Rejected Candidates

The initial correctness fix collected retained output through the streaming
sink. Its CLI CPU regression was 31.26%, so it was rejected. Returning to the
stdlib accumulating buffer and adjusting chunk-reader/call boundaries did not
recover the lost performance.

| Candidate, twelve pairs | Streaming CPU change | CLI CPU change |
| --- | ---: | ---: |
| Sink-backed retained output | +4.28% | +31.26% |
| Stdlib accumulator with bounded chunk reader | +2.39% | +28.49% |
| In-place reader bound | +4.23% | +32.75% |
| Isolated retained decoder call | +4.24% | +29.11% |

Additional three-run CLI screens tested isolated parser/loop calls, transactional
probability-table replacement, forced decode-step inlining, and the stdlib loop
shape. All remained slower. A failed copy onto a read-only saved executable
also caused a partial repeat of the initial candidate; it was stopped after
hash verification exposed the mistake. Its samples and incomplete JSON remain
under `aborted_initial_repeat`, and are not attributed to a new candidate.

Disassembly showed extra range-bit function calls in literal loops in slow
candidates. Several inlining changes failed to recover the speed, so this is
an observation, not a complete causal explanation. The final retained adapter
writes directly into the size-bounded final output allocation and records the
dictionary-reset position. It removes the growing intermediate buffer and
final copy while retaining stdlib LZMA processing. The full paired run above
recovered baseline CLI performance.

## Reproduction

Build both revisions with `./build` and retain their `z7z` and
`z7z-verify-bench` binaries under distinct names outside the checkout.
Generate the Gaussian payload using `tools/random`, seed 271828, mean 128 and
standard deviation 20, following the commands in
[the September 4 report](2026-09-04-deflate.md#reproduction-and-provenance).
The measured archive SHA-256 is
`a0ca426466073975fbc94283b2d208ee38a660d1d622a467e5f702064d3c5912`.

For each binary, the streaming command is:

```bash
taskset -c 24 /path/to/z7z-verify-bench /path/to/gaussian-LZMA2.7z 10
```

The retained command is a Bash loop invoking `z7z --no-progress t ARCHIVE`
ten times, failing immediately on a nonzero exit. Use
`hyperfine --warmup 1 --runs 1 --export-json PAIR.json -n before COMMAND -n after COMMAND`
for twelve pairs, reversing command order on odd pairs. Raw JSON preserves the
exact commands used. RAM scripts and binaries were kept under
`/dev/shm/z7z-flush-fix-20260912` during the investigation.

Correctness evidence is separate from performance: three archive regressions
were observed failing before the fix, and an independent executable-only
[256-value oracle sweep](../../docs/research/2026-09-12-lzma2-flush-oracle.md)
supplies the acceptance set tested across retained, sink and pull decoding.
Allocation-failure tests also exposed unsafe stdlib reset ownership on OOM;
the adapter now allocates replacement probability storage before freeing the
old table. The public result remains a structural error without a named finding
or byte-offset diagnostic.
