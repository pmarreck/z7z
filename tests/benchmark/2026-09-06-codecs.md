# Codec Integration Measurements

Measured 2026-09-06 EDT on AMD Ryzen Threadripper 3990X, Linux x86_64,
Zig 0.16.0, ReleaseFast. Both comparison binaries came from ./build (Nix).
[Raw samples](2026-09-06-codecs.json) retain the initial measurements, contended
comparisons, and subsequent alternating pairs. No samples were discarded.

## New Methods

Hyperfine used three warmups and twelve measured runs for each command. Times
include process startup and one archive read, followed by in-memory verification.
CPU is user plus system time. Build activity was present; these first measurements
were not pinned. The Delta run had statistical outliers.

| Fixture | Iterations | Wall | CPU | Throughput |
| --- | ---: | ---: | ---: | ---: |
| Deflate64, 98,304 bytes, 49,152-byte history | 100 | 82.06 ms | 81.33 ms | 114 MiB/s |
| BZip2, 1,200,000 repeated bytes, single block | 50 | 351.85 ms | 349.18 ms | 163 MiB/s |
| BZip2, 210,000 bytes, three blocks | 50 | 138.30 ms | 136.89 ms | 72 MiB/s |
| ARM64, 65,539 seeded random bytes | 1,000 | 317.19 ms | 314.71 ms | 197 MiB/s |
| RISC-V, 65,539 seeded random bytes | 1,000 | 447.29 ms | 443.72 ms | 140 MiB/s |
| Delta distance 3, 1,031 bytes | 10,000 | 86.43 ms | 85.63 ms | 114 MiB/s |

These methods were unsupported in baseline 075ecadc4200706d0c362afa699da47af83b31c9,
so the table establishes initial throughput, not speedups. Small fixtures include
substantial per-archive metadata/allocation overhead. Fixture recipes and oracle
hashes are in src/fixtures/{deflate64,bzip2,filters}/provenance.json.

## Existing LZMA2 Path

The initial CPU-24 comparison and four-group ABBA repeat were disturbed by build
activity. The unchanged baseline varied by 25% between ABBA groups; that run
cannot establish a decoder speedup or slowdown by itself.

After those builds finished, twelve short pairs alternated before/after order.
Each command verified the same seeded 1 MiB Gaussian LZMA2 archive ten times,
with one warmup and one measured run per command per pair. All twelve after/before
ratios exceeded one. Mean wall time was 755.25 ms before and 788.66 ms after.
Median paired wall and CPU increases were about 4.8%. This regression is being
investigated before shipment; it must not be described as measurement noise.

An isolated one-call `never_inline` LZMA2 candidate improved its matched local
control by 4.62% CPU across twelve pairs. Canonical Nix builds disproved that
candidate's usefulness: twelve new three-way pairs measured mean wall/CPU times
of 743.99/738.55 ms for baseline, 781.69/775.85 ms for initial integration, and
788.53/782.57 ms for the candidate. The local and Nix compiler invocations have
different source paths/module layouts. No microarchitectural cause was proven.
The failed candidate and all samples are retained under `first_nix_candidate`.

The accepted candidate instead prevents inlining the BZip2 sink call. This
restores the shared dispatch frame from `0x6b08` to `0x5028` (baseline `0x5008`),
while preserving the original LZMA2 call and decoder instructions. Twelve
alternating three-way Nix pairs, with the same Gaussian workload, measured:

| Executable | Mean Wall | Mean CPU |
| --- | ---: | ---: |
| Pre-expansion baseline | 743.88 ms | 738.52 ms |
| Initial codec integration | 782.60 ms | 777.00 ms |
| BZip2 call boundary | 743.50 ms | 738.24 ms |

The final candidate improves CPU by 4.99% against initial integration and is
0.04% below baseline, effectively recovering the regression. This is evidence
for this workload and x86_64 machine; other-platform runtime performance has
not been measured. No codec algorithm, CRC check, or allocation rule changed.

Four-pair screens also covered uniform LZMA2, both Deflate payloads, BZip2 RLE
and multiblock inputs, Deflate64 history, ARM64, and RISC-V. Apart from RLE,
CPU deltas against initial integration were improvements or at most +0.76%.
The first RLE screen measured +5.53% with substantial system-time variation.
Twelve three-way RLE pairs then measured 349.66 ms CPU for initial integration,
349.36 ms for the rejected LZMA2 candidate, and 349.34 ms for the BZip2 boundary.
The RLE slowdown did not repeat; both datasets remain in the raw report.
